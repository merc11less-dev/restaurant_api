# Restaurant Booking API

REST API для бронирования столиков в ресторане.

## Описание

API предоставляет возможность создавать, получать, просматривать и отменять бронирования.

Основные возможности:

* создание бронирования;
* получение списка бронирований;
* фильтрация бронирований по дате;
* получение бронирования по идентификатору;
* отмена бронирования;
* проверка корректности введённых данных;
* предотвращение повторного бронирования одного времени.

## Запуск

```bash
docker compose up --build
```

После запуска приложение доступно по адресу:

```text
http://localhost:8000
```

## Использование

### Swagger UI

```text
http://localhost:8000/docs
```

### Эндпоинты

#### Создание бронирования

```http
POST /bookings
```

#### Получение списка бронирований

```http
GET /bookings
```

Для фильтрации по дате:

```http
GET /bookings?date=2026-09-15
```

#### Получение бронирования по ID

```http
GET /bookings/{id}
```

#### Отмена бронирования

```http
DELETE /bookings/{id}
```

Отмена изменяет статус бронирования, но не удаляет запись из базы данных.

### Валидация

При создании бронирования проверяются:

* имя;
* номер телефона;
* дата бронирования;
* время бронирования;
* количество гостей.

Дата бронирования должна находиться от текущего дня до 90 дней вперёд.

Доступное время — 1 час с `12:00` до `22:00`.

Количество гостей — от 1 до 12.

Для одной даты и времени допускается только одно активное бронирование.

## Почему выбрана такая архитектура

Проект разделён на несколько слоёв с отдельной ответственностью.

`app/api` отвечает за HTTP-уровень: роуты, схемы запросов и ответов и обработку HTTP-ошибок.

`app/application` содержит прикладные сценарии. Например, `BookingService` отвечает за создание, получение и отмену бронирований.

`app/domain` содержит бизнес-сущности, статусы, доменные ошибки и протокол репозитория.

`app/infrastructure` отвечает за техническую реализацию работы с базой данных и SQLAlchemy.

Для репозитория используется `Protocol`. Application-слой зависит от контракта `BookingRepository`, а не от конкретного `SqlAlchemyBookingRepository`.

Такое разделение позволяет изолировать бизнес-логику от инфраструктуры, упростить тестирование и при необходимости заменить реализацию хранения данных без изменения application-слоя.

## Миграции базы данных

Для управления структурой базы данных используется Alembic.

Проверить текущую миграцию:

```bash
docker compose exec app python -m alembic current
```

Применить миграции:

```bash
docker compose exec app python -m alembic upgrade head
```

Файлы миграций находятся в директории:

```text
alembic/versions/
```

## Тестирование

Для запуска полного набора тестов используется отдельный Compose-файл:

```bash
docker compose -f docker-compose.test.yml down -v --remove-orphans
docker compose -f docker-compose.test.yml up --build --abort-on-container-exit --exit-code-from tests
docker compose -f docker-compose.test.yml down -v --remove-orphans
```

Тесты выполняют реальные HTTP-запросы к запущенному FastAPI-приложению и проверяют:

* создание бронирования;
* получение бронирования;
* получение списка;
* фильтрацию по дате;
* отмену;
* повторное бронирование освобождённого времени;
* конфликт бронирований;
* валидацию входных данных;
* ошибки `404`.
